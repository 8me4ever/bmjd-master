# BMJD岗位持续补全工具

打开同目录的[BMJD岗位持续补全.html](BMJD岗位持续补全.html)，即可按职能寻找可用代码、填写岗位名称及JD，逐步补全BMJD。HTML约2.92MiB，包含全部数据和页面程序，无需安装，也不调用外部服务。请使用较新的Chrome、Edge或Safari。

## 新增一个岗位

1. 在“所属职能”输入或选择现有263类规范职能之一。
2. 判断是否属于已有专业方向：同一专业方向补充不同层级时选择已有职责系列；不同专业方向选择“新建职责系列”，填写系列名称。
3. 选择1—7级，查看自动建议码和该系列的占用位置。代码只读，保存时再次根据最新占用分配。
4. 填写规范岗位名称，选择至少一个适用行业；按原有格式填写4或5条JD，每行一条，可全部编号或全部不编号。建议写清岗位的行动、工作对象和职责边界，尽量跨行业通用。
5. 点击“保存新增岗位”。记录显示在下方；可查看JD、修改尚未并入基库的新增内容，或撤回、恢复原码。
6. 完成一批录入后，下载“完整主库JSON”和“增量备份JSON”。后续在其他设备继续时，先导入最新文件，再录入。

代码格式沿用原规则：两位字母职能码段、两位职责系列序号、末位岗位层级。同一职责系列内每个层级只能有一个代码；不同专业方向使用新的前四位系列码。已有系列某层级被占用时，工具不会擅自改成其他层级。

## 保护现有代码和JD

内置全局主库为BMJD-JD-REVIEW-20261029-02：9,111岗、263职能、3,077职责系列、11行业。工具保留其岗位ID、名称、代码及JD；不会修改仓库原文件或行业子库。行业专业JD优化版本继续独立使用，不能将行业子库当作全局主库导入。

编码分配同时避让原表及历史版本：共登记13,164个代码、3,908个职责系列前缀，其中4,053个代码不在当前主库中，仍不回收。撤回的新增岗位也继续保留代码和系列。研发新系列沿用R段，避让原非研发RA、RC、RM、RP段；原职能可继续在其既有专属码段内扩展。

岗位主名称及历史别名均用于查重，忽略空白、大小写、全半角及不可见字符的差异。工具不能自动判定语义近似岗位是否应归并；录入前仍应搜索已有岗位，核对专业方向。新增JD标记为用户人工编写，不伪造原BMJD来源或专业审定记录。

## 保存与文件

正常情况下，新增内容自动保存在当前浏览器的IndexedDB中；同一浏览器、同一工作库的多个窗口通过事务在保存时再次配码，避免重复占用。浏览器禁用存储时，页面明确提示“仅本次会话”，仍可导出备份。

- **完整主库JSON**：保留全部原岗位，追加当前活动新增岗位，更新系列索引及统计，并附补全登记和占用记录。可在新设备导入作为下一轮基库。
- **增量备份JSON**：包含新增、撤回和已并入记录，以及历史占用登记；适合备份和合并。相同版本重复导入不会重复建岗；不同版本、代码或系列冲突会整批拒绝，不会部分覆盖或静默改码。
- **新增岗位CSV**：只导出本机当前活动新增记录，含名称、代码、职能、系列、行业及JD，便于Excel查看；不能作为完整备份导入。
- **导入完整主库**：必须保持现有基库全部岗位的身份字段，允许追加岗位及载入权威主库JD更新。已包含在新基库的新增记录变为只读“已并入基库”；未并入的本机新增继续保留。退出编辑或撤回并不会删除历史占用。

不同浏览器、设备、私密窗口或不同来源地址可能使用独立存储。移动或重命名HTML后也不应假定原记录仍可见；请先下载JSON备份，清除浏览器数据前尤其如此。不要只保存HTML而遗漏自己导出的JSON。

离线工具没有跨设备的中央锁。多人同时使用各自副本，可能选中相同新代码；应先合并最新主库及增量，再继续录入。遇到冲突请保留双方文件，核对后在统一工作库重新登记冲突的新岗位，旧代码不会自动改写。已经导出并使用的代码需要由主库维护者统一协调。

## 维护与验证

源码在`completion_tool/`；不使用第三方运行库。构建脚本使用Python标准库，把原主库和历史占用信息压缩嵌入单个HTML。

```sh
python -B tools/build_completion_tool.py --check
node --test completion_tool/completion-core.test.js
python -B tools/check_completion_browser.py --report /tmp/BMJD浏览器核验.json
```

重新生成使用`python -B tools/build_completion_tool.py --write --output-dir 新版本目录`，脚本拒绝覆盖已有不同内容。原主库指纹及构建输入详见[内置数据与构建核验](内置数据与构建核验.json)；交互测试结果见[浏览器核验](浏览器核验.json)。浏览器测试另需Playwright和Chromium，不影响交付HTML的直接使用。

当前测试环境的受管Chromium阻止直接访问`file://`，测试采用仅本机的HTTP临时服务，并断网验证新增和导出，不绕过浏览器策略。HTML不依赖网络；若个人浏览器也受相同管理限制，应使用组织允许的本地访问方式。已核验范围以报告为准，不把本机HTTP测试称为所有浏览器的本地文件测试。
