## 划分及唯一性规则

1. 行业名称来自原版BMJD的11个行业Excel，并与修改版6核对；不按当前职能名称或JD关键词另造行业。
2. 依据既有“来源去向映射”中的原工作簿、行业、sheet及活动来源，将岗位归入对应行业。逐岗交叉验证现有`industries`标签，两者完全一致。
3. 同一个岗位有多个行业的原始来源时，进入对应多个一级子库，始终保留父库同一ID、名称、代码和JD。跨行业重复出现的相同代码表示共享同一岗位，不能重新编码成多个岗位。
4. 每个行业内同一岗位只出现一次；同一行业多个原始Excel行或多个同义来源不会重复建岗。
5. 本轮只按已有行业范围拆分，不将所有通用岗位额外复制到全部行业。原23条暂缓来源只在行业来源总账保留，不恢复为活动岗位。

11个子库共 **19,018条岗位记录**，对应 **9,111个不同岗位**。其中 **2,042岗跨行业共用、7,069岗仅属于一个行业**。子库合计数量大于父库数量来自跨行业共用，不是增加岗位或产生重码。

## 数据结构与原文追溯

- 每份`岗位主库.json`包含本行业岗位、职能列表、职责系列和本行业原始来源总账，以及父库版本与SHA256。
- 每个岗位复制父库所有原字段，仅新增`industry_membership`，记录当前一级行业和本行业的真实`source_ids`。原`industries`、`source_ids`、JD条款依据及身份推定标记原样保留。
- 原JD依据可能来自同一共用岗位的其他行业，这是沿用统一主库JD的上下文；`industry_membership.source_ids`才是本行业归属依据，不将其他行业引用伪称本行业来源。
- 子库职责系列及职能列表仅引用本子库内的岗位ID。原来源中的旧码和旧名称仅用于追溯，不作为当前有效岗位代码和名称。
- [岗位行业索引](岗位行业索引.json)提供全部9,111岗到行业子库的路径；[行业划分依据](行业划分依据.json)列明22个原工作簿的实际位置和本轮规则。

Excel和TSV包含：岗位ID、岗位代码、岗位名称、职能、职责系列、层级、所属子库、全部适用行业、完整岗位JD。完整的原文引文、依据类型和源级去向保存在JSON中。

## 核验与复算

生成端49项检查和独立产物232项检查全部通过。独立检查器直接读取父库、原行业来源、11份实际JSON/TSV/Excel及总工作簿，不使用生成端的通过标记作为结论。验证全部原字段未改、行业无串入或遗漏、来源守恒、子库唯一性以及导出逐字段一致。

仓库根目录运行：

```bash
python -B tools/split_industry_masters.py --check
python -B tools/audit_industry_masters.py --check
python -B -m unittest discover -s tools -p 'test_split_industry_masters.py' -v
python tools/project_files.py --check
```

核心生成与独立检查仅用Python标准库，重新导出Excel需要`openpyxl`：`python -B tools/export_industry_masters.py`。工具拒绝覆盖已有不同内容；后续变更建立下一版本，保留父库与当前行业子库。
