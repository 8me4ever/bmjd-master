# 岗位编码自审结论

本轮由Codex独立审查，后续规则判断与核定也由Codex负责，不设置外部专家确认步骤。

**当前9,111个岗位、9,111个唯一有效代码：重复代码0组、非法代码0个、代码与层级冲突0个。** 全部现有代码保持不变。

## 已核实

- 代码严格采用两位大写字母＋两位数字＋1—7级；同时检查大小写、全半角、空白和隐形字符造成的潜在冲突。
- 岗位ID、标准名称均唯一；名称括注职级、代码末位和层级字段一致。
- JSON、TSV、正式Excel按ID逐岗位、逐字段一致，均为9,111行；正式Excel同时纳入项目清单，便于以后复核。
- 职能、系列、码段一致；所有来源目标ID与当前代码一致，普通来源唯一归岗，两条灯光授权来源保持原角色，23条暂缓来源未恢复。
- 冻结基线8,932个ID与前版8,925个ID的映射逐来源核对，拆分没有把其他来源的后继岗位误带入。

独立审查共 **28/28项通过**。检查器不导入主库生成器，也不沿用其通过标记，而是重新读取真实JSON、TSV和Excel核对。完整证据及输入文件指纹见[编码自审报告](编码自审报告.json)。

## 四组共享别名的判定

发现的4组重合都是“测试工程师”等历史泛别名，均不是重复的有效岗位代码：

| 泛称 | 当前代码 | 自审判定 |
|---|---|---|
| 高级测试工程师 | RT014 / TE024 | 产品测试与软件测试保留不同对象 |
| 测试工程师 | RT015 / TE025 | 产品测试与软件测试保留不同对象 |
| 初级测试工程师 | RT016 / RT026 | 明确产品测试与未限定对象的通用测试分别保留工作身份 |
| 测试经理 | TE003 / TE023 | 通用测试管理与明确软件测试管理分别保留工作身份 |

已查看上述岗位的原表名称、职能和细分，决定保留现有范围及代码，不因历史泛称相同强行并岗。具体判断保存在[编码自审规则](编码自审规则.json)。别名只用于检索，岗位定位和下一阶段JD回填使用当前代码、ID及来源映射。

原推定标签保留作内部判断依据，不是等待他人审批的状态。本轮确认的是编码、引用及交付格式的一致性；JD保持下一阶段处理。
