## 完成的含义与推定边界

本轮完成的是**全库名称代码规则统一工作版**。全部岗位已有具体名称、职能、系列、工作层级、唯一代码和来源去向，原3,092个推定基线均有具体目标及处置；不是批量改成“已查看”。

当前仍有 **3,489个工作岗位含透明推定**，包括继承的身份不确定性、同义名称范围、分类调整、测试对象范围和层级差异。本轮没有把原3,092岗的不确定性无依据取消。这个数按当前工作岗位统计，不能与原基线3,092直接相减解释进度。

“未处理0”表示名码处置已覆盖。原工作假设按依据保留并由Codex继续核定；编码唯一性本次已经独立验证。所有假设、原表定位、原名原码和对下一阶段的范围限制分别保存在[全量岗位处置台账](全量岗位处置台账.json)与[透明推定清单](透明推定清单.json)。本轮不声明JD或专业职责已经审定。

## 如何统一

1. 提取19,226条活动来源在原版、修改版6中的A:G元数据，按行业、行号和名称核对，不用岗位JD反推岗位名称，也不按已迁移的旧码误接来源。
2. 对215组多名称系列逐组保存规则，其中51组按明确专业对象拆分，其余在同职能、同对象、同级范围保留同义或原有双称谓证据；保留所有原名称。
3. 单一原名优先恢复有据名称，规范全半角、空白、明确文字重复和已列明的同义词；保留C++、C#等技术身份符号。
4. 全库同专业、同级且有原名/原细分等价证据的工作身份归一，行业和旧部门标签不另建一份。不同专业对象、不同职务或不同工作层级保留区分。
5. 保留有效既有职业梯队和代码，纠正混合对象或转职能时才重新分配；保留全部旧ID、旧码到当前目标及逐来源去向。
6. 64组同名跨职级使用已有工作职级作名称括注，跨专业时同时注明专业；职级括注用于显示已有工作层级，级差依据由Codex核定并留痕。同级同名必须先解决归并或对象区分，不能加序号掩盖重复。

## 关键修正与边界结论

- 门店会计、门店财务主管归财务，不再并入人力资源；原人事/人力资源同义称谓归一。
- 营养师与客户关系拆开，驻店药师与导购拆开；原料血浆开发保留原名专业对象。
- 实物结构设计、结构组装工艺与软件开发拆开；UI设计与UI开发分开，泛研发不自动变成软件岗位。
- 寿险理赔与财险理赔分开；标准化与产品导入、生产统计与设备管理等按明确原名对象处理。
- 软件测试、产品测试分别确定；通用“测试工程师”不能把两个专业对象串成一岗，范围推定单列。
- 泛算法、架构设计的旧分类分叉归一；投资/投资管理同级按投资职业工作归并。通用项目专员/项目管理专员归一，去掉没有原名称依据的营销限定；明确职业教育、产品等对象仍保留。
- 会员中心服务与会员营销、技术维修工与工程维修经理、物流订单与销售订单保留明确工作分支。[边界统一结论](边界统一结论.json)逐项给出处置，不再留作未处理队列。
- 报关组长原5级与报关主管原4级分开；只在已确认的配货特例中把组长并4级主管，配货助理仍6级。
- GM001、HR963、DP203—206、灯光两岗及原授权边界保持。原非研发RA/RC/RM/RP码段保持；新增研发类代码仍以R开头。

## 重算与验收

仓库根目录运行，Python >=3.10，仅标准库即可重算本版：

```bash
python -B tools/audit_job_codes.py --check
python -B tools/unify_all_names.py --check
python -B -m unittest discover -s tools -p 'test_*.py' -v
python tools/project_files.py --check
```

`--check`重新提取原表、应用规则、计算全量名码及映射并逐文件比对；不会覆盖有变更的文件。`--write`首次生成或验证相同内容，已有不同内容必须另建下一版本，不重置用户改动。测试中既有JD接收回归需要环境已有的jsonschema；本轮未重新生成或回填任何JD。

下一阶段按本版ID和逐来源映射重新定位JD，保留旧稿与逐条依据。身份拆分不能一稿多用；匹配名称再决定保留或重写，不能为迁就旧错贴JD改回错误名称。
