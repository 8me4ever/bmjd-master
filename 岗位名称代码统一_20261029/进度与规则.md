## 继续执行的原规则

- 一个标准岗位只有一个当前有效代码，代码五位且末位与层级一致。相同职能、工作对象、同层级的等价身份归并；不因行业标签或旧部门不同重复建岗。
- 先确定名称。不能为了迁就错贴JD反向修改岗位名称；本批只提取原表A:G的名称、职能、细分、代码等元数据，不做JD匹配。
- 主管、组长、专员、助理及工程师等名称不能仅按代码末位机械替换。原等级有问题时单列推定依据，不能写成用户逐项确认。
- 实质不同的岗位分开。归并、拆分、改名、改级、改码都保留基线ID、原名原码和来源去向；新身份使用新ID，不静默挪用旧ID。
- 保持GM001、HR963、DP203—206、配货主管4级/助理6级、灯光两岗及授权分配、原非研发R段边界。23条暂缓来源继续暂缓。

## 主要名称代码结论

**去掉重复身份。** KOL运营3—6级统一到AE003—AE006；应收应付3—6级统一到FA103—FA106；剪切/切割技师5—7级统一到PD575—PD577；仓储总监、经理、主管统一仓储职能的对应身份。原行业来源合入同一岗位，退役代码保留映射。

**先按原名拆开锅炉、暖通与结构。** 原锅炉工程师3—6级分别建立BC173—BC176，不再按混杂JD改名为暖通。暖通经理、主管、工程师、初级工程师保留BC003—BC006，暖通领班另立AN085。DP045只保留结构设计来源，暖通来源回到对应暖通岗位；DP106保留暖通设计助理来源，不与工程执行的初级暖通工程师混合。岗位职责和JD是否适用留到下一阶段。

初级暖通工程师三条同名来源统一到BC006：制造、能源化工原6级提供梯队依据，地产原5级推定调整为6级，原级仍在来源映射保留。BC005、BC006的原混合ID均退役，当前暖通工程师、初级暖通工程师使用新ID。该层级纠正属于继续推定，不写成用户确认。

**库管组长不自动升为主管。** AX014使用仓储主管4级；原BY146库管组长按原6级另立AX086，保留层级推定待进一步核定。仓储副总经理恢复原名，代码AX011；仓储专员/助理/员使用AX075—AX077。原AX014的混合ID退役，两个身份使用可追溯的新ID。

**报关专员和报关员分别保留原级。** LO095为报关专员5级，原报关员6级来源另立LO096，不因同属报关忽略级别差异。

**恢复被泛化或误换的名称。** 运输司机不称司机助理；物流管理员不称综合员；初级工艺设计师不擅加工业建设布置限定；原料血浆开发助理保留开发对象；高级算法工程师不因4级自动变成主管；会员中心经理不统一叫会员营销经理。助理结构工程师去掉重复的“工程”。

## 文件与核验

- 名称代码决策.json：逐项名称代码调整、归并、拆分、等级推定与理由。
- 基线名称代码映射.json：全部8,932个旧ID和旧码的当前目标；检索历史代码时必须结合版本和ID。
- 来源去向映射.json：每条原始名称、原码、文件行号及当前目标；普通来源唯一归岗，原灯光授权来源保持两目标。
- 推定岗位名码台账.json：3,092个基线推定岗的本轮状态，以及本批额外复核的非推定岗；未审岗位保持待复核。
- 原表名称职能证据.json、输入指纹.json：原表元数据和工作簿指纹；原版与修改版按行业、行号和名称共同核对，不能仅用可能已迁移的旧码连接。
- 核验报告.json：一岗一码、合法层级、全量映射、来源守恒、确认约束和无JD字段等检查结果。

在仓库根目录运行（Python >=3.10，仅标准库）：

```bash
python -B tools/name_code_master.py --check
python -B -m unittest discover -s tools -p 'test_name_code_master.py' -v
python tools/project_files.py --check
```

`--check`从冻结基线及本批决策重算并比对当前输出。`--write`首次生成或重复验证相同内容，不覆盖有变化的工作文件。后续修改建立下一版本；只有名称代码全量确定后才启动JD阶段，并使用完整ID/来源映射重新定位旧稿，不按当前名称或行号直接覆盖。
